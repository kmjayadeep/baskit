## Problem

`_syncCurrentUserMembershipProfile` performs Firestore batch writes to update
member profile fields across all user lists, but lacks error handling around
both individual document processing and batch commits.

Two issues:
1. If `batch.commit()` throws (network failure, permission denied, etc.), the
   entire method crashes and subsequent batches are never committed
2. If parsing a single document's data throws (malformed data), the entire
   sync aborts and other documents are never processed

## Solution

- Wrap both `batch.commit()` calls in try/catch blocks and record errors via
  `FirestoreServiceContext.recordNonFatal()` for monitoring
- Wrap individual document processing in try/catch so one bad document doesn't
  abort the entire sync
- Continue processing remaining documents after any error

This follows the same error handling pattern used throughout the rest of the
codebase (see `initializeUserProfile`, `getDefaultVoiceListId`, etc.)
